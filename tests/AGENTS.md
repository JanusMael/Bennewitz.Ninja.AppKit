# AGENTS.md — `tests/`

The families' test projects, and the apps AppServices' entry-point tests run.
`tests/Directory.Build.props` makes each test project an xUnit v3 test executable on
Microsoft.Testing.Platform that is never packed. A test that scans shipped projects
scans its own family's, the `src/` folders named for it.

## AppServices

The test project `AppServices.Tests`, referencing every shipped project. `tests/Directory.Build.props`
makes it an xUnit v3 test executable that is never packed. Beside it, `EntryPointProbe`,
`EntryPointWebProbe` and `DesktopProbe` are apps, not tests: each has a `Directory.Build.props` of its
own, which imports the root one in place of this directory's and sets `IsPackable` to false.
`DesktopProbe` is an Avalonia app on the headless platform, run as a child process.

### Rules

| Rule | Why | Guarded by |
|---|---|---|
| Tests run on Microsoft.Testing.Platform | `dotnet test` takes `--solution` and rejects VSTest-only switches | `global.json`, `test.runner` |
| `tests/Directory.Build.props` imports the root props explicitly | Without it the test project silently loses the root's target framework and nullable settings | the import line itself |
| The assembly runs serially | Some tests change process-wide static state (`AvaloniaDiagnostics`, Serilog's `Log.Logger`, `NativeErrorDialog.SuppressForTests`), and the headless tests share one session and dispatcher | `Parallelization.cs`; `HeadlessSessionTests` guards the one-session premise |
| A test that changes static state restores it in `Dispose` | The next test inherits it | `AvaloniaDiagnosticsHookTests` (`AvaloniaDiagnostics.ResetForTests`, which also takes the UI-thread handler off its dispatcher and resets its gate, its counts and its dialog seam), `NativeErrorDialogTests` (`NativeErrorDialog.Reset`), `DialogGlyphButtonTests` (`DialogMessageContent.ResetForTests`, which puts the link opener back), `DialogStringsTests` (`DialogStrings.ResetForTesting`, which also forgets the keys whose failure was logged) |
| `BenignExceptionTable` is the one table of the benign rule: every test of either copy, and of what each drives, reads its rows, and none keeps cases of its own | The two copies exist because the packages may not share an internal; held to two tables, they would drift apart unseen | `BenignExceptionRuleTests.The_table_holds_every_case_of_the_rule`, which pins the row count |
| A test that reads a line the packages write to Serilog reads its message template and its property values, never `RenderMessage()`: it compares the template with one in `PackageLogLines`, or with the entry point's own in `AppMainTests`, or reads the whole line through `LogLineForm.Is`, which also holds it to the family's form. `ShellLauncher`'s line is text, not a template, and is compared as it is | `RenderMessage()` quotes every string itself, so a test reading through it reads a line no sink writes. `LogLineFormTests` holds every template in `PackageLogLines` to the form, so the coming CodeQuality rule is not these lines' only guard: it cannot see the templates behind `UiThreadExceptions`' guarded `Write` | `LogLineFormTests.The_table_holds_every_template_a_test_reaches`, which pins `PackageLogLines`' count, and `Every_package_template_holds_the_form`; that no test reads `RenderMessage()`, review alone |
| A test that asserts over every event of an `AppMain` run with `EntryPointOptions()` leaves out the entry point's two lines by their tags, `[App.Start]` and `[App.Exit]` | The options write both in every such run, so a test that took them for lines it did not expect would fail on every run | `UiThreadExceptionHandlerTests.Every_row_abandoned_in_a_task_is_logged_shown_and_written_on_stderr_as_its_verdict_says`, which also reads its log opening with the start line and closing with the exit line |
| A UI-thread handler test installs, `Post`s a throwing job, runs `RunJobs()` and asserts what the handler did inside one `Session.Dispatch`, with a fresh exception per throw, and at Debug wherever it asserts a Debug line | Each dispatch gets a dispatcher of its own; only a posted job's exception reaches `UnhandledException`; the dispatcher offers an exception object once; the default minimum, Information, drops a Debug line | `UiThreadExceptionHandlerTests` remarks |
| A test of a task exception's dialog runs `RunJobs()` inside the dispatch that installed the hooks before it asserts what was shown, and records the thread each dialog was asked for on | The dialog is posted, and a dispatcher the session has moved past runs no more jobs, so an assertion that nothing was shown would pass whatever the code did; only the thread tells a posted dialog from one opened on the finalizer thread | `UiThreadExceptionHandlerTests` remarks |
| An unobserved-exception test of the benign filter collects garbage before its run hooks in | A task an earlier test abandoned would otherwise reach this run's hook and write to its stderr | `AppMainTests` remarks |
| A test that leaves task exceptions nobody observed collects garbage before it ends | The runtime raises one at whichever collection finds its task, into whichever run is hooked in then, and that run reports it on stderr. Avalonia 12.1.3 also puts each posted job's exception in the job's task, which nothing reads, so every UI-thread handler test leaves some: in CI's Windows order they reached the web probe's run | `UiThreadExceptionHandlerTests` remarks and `Dispose`; `AppMainTests` collects each task it abandons inside the run that is to see it |
| Headless isolation is per test, and there is no warm-up | Each dispatch builds a fresh application, so a warm-up changes nothing. Switching to `AvaloniaTestIsolation` per assembly changes what every test shares and needs its own evidence first | `HeadlessSessionTests` remarks |
| A share test never passes text without a URI on Windows or macOS | That path runs the real `clip.exe` or `pbcopy` and overwrites the developer's clipboard; every other path goes through the launcher injected into `DefaultShareService` | `DefaultShareServiceTests` remarks |
| A platform-bound test skips with `Assert.Skip` or `Assert.SkipUnless`, never passes silently | A skip is visible in the report; an early return reads as a pass | `ShellLauncherWindowsTerminalTests`, whose launching tests carry `[Trait("Category", "Integration.WT")]` or `"Diagnostic.WT"`; `LaunchResultTests` |
| `LayeringTests.Tiers` and `LayeringTests.ForeignFamilies` are the one table of what may reference what | `AssemblyQualityTests` reads them for BNAQ1003; a copy is the list that silently rots | `AssemblyQualityTests.BNAQ1003_no_assembly_references_what_its_tier_forbids` |
| The layering guards keep both the csproj check and the reflection check | The compiler omits an unused reference from the assembly, so a declared-but-unused bad reference is invisible to reflection | `LayeringTests` remarks |
| The vacuity guards stay | Every other assertion iterates a list, and an empty list passes all of them; a rule that could not load part of what it was given reports clean on the rest | `LayeringTests.Every_tier_named_here_actually_exists`, `PackageMetadataTests.There_is_something_to_check`, `AssemblyQualityTests.Every_shipped_assembly_is_in_the_scan`, each rule's `Inspected > 0` and empty `Skipped` |
| `DialogAccessibilityTests` pins each window's interactive controls by their ids, in the window's row of `DialogWindows`, and every window class the Avalonia package declares has a row | A new control must add its id; a lower count means the walker lost something; a window missing from the table is checked by nothing | `DialogAccessibilityTests` remarks; `Every_window_class_the_package_declares_is_in_the_table` |
| `DialogColorTests.Colours` lists where every window in `DialogWindows` shows a colour, with none where it reads no key, and each test reads a window's colours against the package's dictionary or a host's, never against the plan's table, which one test holds the dictionary to | A window added to the table of windows is checked for its colours too; one that starts reading a key without its row merges a dictionary, and one listed with a colour it no longer shows fails on the count | `Every_window_in_the_table_of_windows_has_its_colours_listed`, `A_window_that_reads_no_key_merges_nothing`; `Each_key_takes_the_plan_s_value_in_Light_and_Dark_and_the_Light_one_in_Default` |
| `DialogStringsTests.KeysShown` lists the keys every window in `DialogWindows` shows, and `DialogWindows.Given` every string a row passes its window; a key read outside a window is in `KeysOutsideWindows`, beside the test of its own that holds it | A window added to the table is walked for its words too, and a string a row passes that `Given` lacks reads as English left behind; a key read nowhere a test looks is a string no host is shown to replace | `Every_window_in_the_table_of_windows_has_its_strings_listed`, `Every_key_is_shown_in_a_window_of_the_table_or_held_by_a_test_of_its_own` |
| `DialogAccessibilityTests` requires a tooltip of every control it requires a name of, from its own `IsInteractive`, and keeps no copy of `BNXQ1011`'s list of input types | XamlQuality's `BNXQ1011` cannot see a control built in C#, so the walker is these windows' only tooltip guard; a second list of what counts would drift from the first | `DialogAccessibilityTests` remarks; `Every_interactive_control_has_a_tooltip` |
| A dialog test shows its window before it presses a key or clicks, presses a button through its automation peer, clicks through the headless mouse only a control that paints a fill, and loads no theme unless it measures one, adding it to its own application's styles | A key reaches a button's `IsDefault` or `IsCancel` only through a shown window's visual tree. The peer's invoke is what UI Automation does. Avalonia 12.1.3 gives every `ContentControl` a default template, so a window shows its content without a theme. The headless mouse finds only what paints a fill: neither text nor a null fill takes the pointer. Each dispatch builds an application of its own, so a theme added there reaches no other test | `DialogInput` remarks; `DialogGlyphButtonTests` remarks |
| After adding, removing or renaming a project, run `repo-conventions grants` | The grants are generated from every project's assembly name, so until the list is regenerated a renamed assembly receives none, and `check` fails | `scripts/repo-conventions.cs check` |
| The console and desktop probes are built and run, never referenced for their assemblies | Each `Program` would sit beside the web probe's, which `WebApplicationFactory<Program>` needs | `ReferenceOutputAssembly="false"` in `AppServices.Tests.csproj` |
| A test of `FailOnUnobservedTaskExceptions`' exit handler calls it with constructed args, and never raises a real lifetime's `Exit` in process | Avalonia raises `Exit` from its shutdown, which then shuts down the UI thread's dispatcher every headless test shares; `DesktopProbeTests` covers the real lifetime in a child process | `FailOnUnobservedTaskExceptionsTests` remarks |
| A test that needs the exit handler's own collection to find a task abandons it faulted through a `TaskCompletionSource`, never through `Task.Run` | A pool thread can still hold a task it ran when the collection comes, so the test would race it | `FailOnUnobservedTaskExceptionsTests` remarks |
| A headless test awaits `Session.Dispatch`, or returns its task, and never blocks on it | Avalonia 12.1.3's session completes a dispatch's task on its own thread without `RunContinuationsAsynchronously`, so the rest of an async test, and xUnit's start of the next test, can run on that thread, where a blocking wait for another dispatch never ends. CI's order hung that way on 2026-11-16 | `FailOnUnobservedTaskExceptionsTests` remarks |
| A test that runs `AppMain` with `EntryPointOptions()` suppresses the native fatal dialog, and fails when its work threw | A work that throws opens the real dialog, which nobody closes on CI, and exits 1, which a test expecting 1 would take for its answer | `AvaloniaDiagnosticsEntryPointTests`, `FailOnUnobservedTaskExceptionsTests` constructors |
| `WebApplicationFactory` is not the proof that `HostAbortedException` passes through | It resolves the host with `stopApplication: false` and never throws it; only a stop on `HostBuilt`, as a design-time tool makes, does | `EntryPointWebProbeTests` remarks |
| A test that needs the native probe skips, visibly, without `ENTRYPOINT_PROBE_NATIVE` | The native binary exists only where CI's aot jobs publish it | `EntryPointProbeTests` |
| A signal test asserts the probe's `probe: flushed` marker, never its exit code alone | .NET reports a child killed by a signal as 128 plus the signal's number, so a probe that SIGINT killed outright reads 130, exactly as a handled Ctrl+C does | `EntryPointProbeTests` remarks |

⛔ **Never weaken an architecture or packaging test to make it pass.** When one fails, the project,
the package list or the workflow is wrong, not the test.

## ScopedEditors

`ScopedEditors.Tests`, the family's test project. `tests/Directory.Build.props` makes it an
xUnit v3 test executable that is never packed. It references the family's three projects under
`src/`, `Avalonia.Headless`, `Bennewitz.Ninja.AssemblyQuality` and `Bennewitz.Ninja.XamlQuality`.

| Folder | What it covers |
|---|---|
| `Architecture/` | `LayeringTests`, `AssemblyQualityTests` (BNAQ1001–BNAQ1005 over every shipped assembly), `PackageMetadataTests`, and the markup guards `ThemeResourceIntegrityTests`, `DangerSurfaceMarkupTests`, `SeverityGlyphFontSizeMarkupTests` |
| `Accessibility/` | XamlQuality's `BNXQ1002` (`AxamlAccessibilityCoverageTests`), `BNXQ1001` (`ExpanderAutomationNameTests`), `BNXQ1007` (`AxamlAutomationIdCoverageTests`), `BNXQ1009` and `BNXQ1010` (`GeneratedRowRuleTests`) and `BNXQ1011` (`AxamlTooltipCoverageTests`) over the package's markup. ### Rules

| Rule | Why | Guarded by |
|---|---|---|
| Tests run on Microsoft.Testing.Platform | `dotnet test` takes `--solution` and rejects VSTest-only switches | `global.json`, `test.runner` |
| `tests/Directory.Build.props` imports the root props explicitly | Without it the test project silently loses the root's target framework and nullable settings | the import line itself |
| Tests run one at a time | There is one headless Avalonia dispatcher per assembly, and it must not be driven concurrently | `Parallelization.cs`; `HeadlessSessionTests.GetOrStartForAssembly_ReturnsTheSameSessionEveryTime` |
| A headless test dispatches a **synchronous** body through `HeadlessUnitTestSession.GetOrStartForAssembly` | An `async` body returns a `Task<Task>` nothing awaits, so the test cannot fail | `HeadlessTestApp`, summary |
| No warm-up dispatch and no shared application across tests without `[AvaloniaTestIsolation]` evidence | With no isolation attribute every dispatch builds a fresh application, so a warm-up proves nothing | `HeadlessSessionTests`, remarks |
| Every scan asserts it inspected something before asserting it found nothing, or says beside the assertion why zero is true; an AssemblyQuality rule that loads assemblies also asserts `Skipped` is empty | Zero findings from a scan that saw nothing, or only part of what it was given, reads as a clean codebase | `AssemblyQualityTests.Every_shipped_assembly_is_in_the_scan` and its `Skipped` assertions; `PackageSources.Markup`; the `Inspected` assertions in each markup guard |
| The markup guards read the project through `PackageSources`, with XML comments stripped | One home for the scope; a binding named only in a comment is not a binding | `PackageSources.Project`, `PackageSources.MarkupText` |
| `LayeringTests.Tiers` is the single table of what each project may reach | `AssemblyQualityTests.BNAQ1003_no_assembly_references_what_its_tier_forbids` reads it too; a copy would rot | `LayeringTests.Every_tier_named_here_actually_exists` |
| A new `LE.*` key used only by hosts goes in `ThemeResourceIntegrityTests.KeysKeptForHosts` with its reason | The list is the only exemption from the dead-token check, and it checks itself | `Every_key_kept_for_hosts_is_still_declared_and_still_unused_here` |

⛔ **Never weaken a packaging, layering or markup guard to make it pass.** When one fails, the
package list, the project or the markup is wrong, not the test. A changed guard is proven by
planting the defect it exists for, watching exactly that test fail, and removing the defect.
